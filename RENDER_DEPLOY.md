# Deploy MummaXpress to Render (10 minutes)

Step-by-step guide to ship **both** the backend (.NET 8) and frontend (Next.js 16) on [Render](https://render.com) using the [`render.yaml`](./render.yaml)
blueprint (services: **`mummaxpress-api`** + **`mummaxpress-web`**).

> Vercel is optional — the frontend can run entirely on Render via
> `docker/frontend.Dockerfile`.

---

## 1. Prerequisites

| You need                                             | Why                                            | How                                                                                          |
| ---------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Azure SQL Database** (or any reachable SQL Server) | Primary data store                             | Free tier: 32 GB on the **Serverless** General Purpose pool, or Aiven SQL Server free trial. |
| **GitHub account** linked to Render                  | Code source                                    | `https://github.com/hellonanoinfy-cyber/quick_Commerce`                                      |
| **(Optional) Resend**                                | Real email OTPs (otherwise OTP prints to logs) | https://resend.com — verify your sender domain.                                              |
| **(Optional) Upstash Redis**                         | Distributed OTP store + SignalR backplane      | https://upstash.com free tier (10 K commands/day).                                           |
| **(Optional) Cloudinary**                            | Image uploads in admin                         | https://cloudinary.com free tier (25 credits/month).                                         |

> All "optional" items have working **demo fallbacks** baked into the backend —
> the app boots cleanly without them.

---

## 2. Connect Render to GitHub

1. Go to https://dashboard.render.com → **Account** → **GitHub** → install the
   Render app on the `hellonanoinfy-cyber` org and grant access to
   `quick_Commerce`.
2. Click **New** → **Blueprint** → pick the repo. Render reads `render.yaml`
   and shows two services: **`mummaxpress-api`** (backend) and
   **`mummaxpress-web`** (frontend).
3. Click **Apply**. Render creates both services but **does not deploy yet** —
   it asks you for the secret env vars first.

---

## 3. Fill in the required env vars

In the Render dashboard, open **`mummaxpress-api`** → **Environment** and paste
the values below. Anything marked **REQUIRED** must be filled before the first
deploy.

| Variable                                              | Value                                                                                                                                                        | Notes                                                                                                                                           |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `ConnectionStrings__DefaultConnection`                | `Server=tcp:<server>.database.windows.net,1433;Database=<db>;User Id=<user>;Password=<pwd>;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;` | **REQUIRED.** From Azure portal → SQL DB → Connection strings → ADO.NET.                                                                        |
| `Jwt__Secret`                                         | Auto-generated by Render (`generateValue: true`)                                                                                                             | Already strong & ≥ 32 chars. To rotate later: `openssl rand -hex 32`.                                                                           |
| `Cors__AllowedOrigins`                                | `https://mummaxpress-web.onrender.com`                                                                                                                       | **REQUIRED.** Your frontend Render URL (comma-separated for multiple).                                                                          |
| `Database__MigrateOnStartup`                          | `true`                                                                                                                                                       | Already set. Applies EF migrations on every cold start.                                                                                         |
| `Database__SeedOnStartup`                             | `true` **for the first deploy only**, then flip to `false`                                                                                                   | Seeds demo products + an admin user.                                                                                                            |
| `ADMIN_PHONE_NUMBERS`                                 | `+91XXXXXXXXXX` (your real phone, E.164)                                                                                                                     | Seeded as admin during the one-time seed. Leave empty to use placeholder you can promote later with `tools/UpgradeAdminUser.ps1 -Phone +91...`. |
| `ConnectionStrings__Redis`                            | `rediss://default:<token>@<id>.upstash.io:6379`                                                                                                              | **Optional.** Leave empty → in-memory fallback.                                                                                                 |
| `Smtp__Host`                                          | `smtp.resend.com`                                                                                                                                            | Optional. Empty = demo mode (OTP in logs).                                                                                                      |
| `Smtp__Password`                                      | Resend API key                                                                                                                                               | Optional.                                                                                                                                       |
| `Smtp__FromEmail`                                     | `noreply@yourdomain.com` (must be verified in Resend)                                                                                                        | Optional.                                                                                                                                       |
| `Otp__EmailHashSecret`                                | Auto-generated by Render                                                                                                                                     | Already strong.                                                                                                                                 |
| `Razorpay__KeyId` / `__KeySecret` / `__WebhookSecret` | From Razorpay dashboard                                                                                                                                      | Optional. Empty = demo payment modal.                                                                                                           |
| `Cloudinary__CloudName` / `__ApiKey` / `__ApiSecret`  | From Cloudinary                                                                                                                                              | Optional. Empty = uploads disabled.                                                                                                             |

> **JWT secret tip:** if you'd rather supply your own, generate one locally
> with `openssl rand -hex 32` (Linux/macOS/WSL) or `[Convert]::ToHexString(
(1..32 | %{ Get-Random -Max 256 }))` (PowerShell), then paste it into
> `Jwt__Secret` instead of letting Render auto-generate.

Click **Save Changes** → Render auto-triggers the first build.

---

## 4. First deploy: seed the database

The blueprint sets `Database__SeedOnStartup=false` by default to keep
re-deploys fast. To seed demo data **once**:

1. After step 3, change `Database__SeedOnStartup` to `true` → **Save & Deploy**.
2. Wait for the deploy to finish (~4 minutes from cold).
3. Watch the logs for `Database seeding completed successfully.`
4. Flip `Database__SeedOnStartup` back to `false` → **Save & Deploy**.

This step is **idempotent** — re-running with `true` won't duplicate rows, but
keeping it `true` adds ~5 seconds to every cold start.

---

## 5. Verify the deploy

Once the status reads **Live**, hit the public URL (Render gives you
`https://mummaxpress-api.onrender.com`).

| URL                        | Expected                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| `GET /health`              | `{ "success": true, "data": { "status": "Healthy", "database": { "status": "connected" } } }`          |
| `GET /api/v1/integrations` | JSON map showing each module's `mode` — `live` for what you configured, `demo` for what's still empty. |

If `/health` returns **503 Degraded**, the DB is unreachable — re-check
`ConnectionStrings__DefaultConnection` and make sure your Azure SQL firewall
allows **Render's outbound IPs** (or enable _"Allow Azure services and
resources to access this server"_).

## 6. Deploy the frontend on Render (`mummaxpress-web`)

The blueprint creates a second **Web Service** using
`docker/frontend.Dockerfile` (Next.js `output: 'standalone'`).

### 6.1 Required env vars (frontend service → Environment)

| Variable              | Value                                                     | Notes                                                                                           |
| --------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `API_INTERNAL_URL`    | Auto-wired from `mummaxpress-api` → `RENDER_EXTERNAL_URL` | If the first build fails, paste `https://mummaxpress-api.onrender.com` manually and re-deploy.  |
| `NEXT_PUBLIC_APP_URL` | `https://mummaxpress-web.onrender.com`                    | **REQUIRED.** Set after you know the frontend URL, then **re-deploy** so the build picks it up. |
| `NEXT_PUBLIC_API_URL` | _(empty)_                                                 | Leave empty — browser uses same-origin `/api/*` rewrites.                                       |

> **Why re-deploy?** `next.config.mjs` bakes `API_INTERNAL_URL` into `/api/*`
> rewrites at **build time**. If it is missing during the Docker build, every
> API call proxies to `http://localhost:5181` and login/catalog break.

### 6.2 Manual frontend service (without Blueprint)

If you created the frontend by hand instead of Blueprint:

| Setting               | Value                        |
| --------------------- | ---------------------------- |
| **Runtime**           | Docker                       |
| **Root directory**    | _(repo root — leave blank)_  |
| **Dockerfile path**   | `docker/frontend.Dockerfile` |
| **Docker context**    | `.` (repository root)        |
| **Health check path** | `/`                          |

**Do not** set Root Directory to `frontend` when using the Docker file above —
the Dockerfile expects paths like `frontend/package.json` from the repo root.

### 6.3 Verify the frontend

| URL                        | Expected                                      |
| -------------------------- | --------------------------------------------- |
| `GET /`                    | Storefront HTML (200)                         |
| `GET /api/v1/integrations` | JSON from backend (proxied via Next rewrites) |

Update **`Cors__AllowedOrigins`** on the **API** service to
`https://mummaxpress-web.onrender.com` if you have not already.

### 6.4 Optional: Vercel instead of Render for frontend

| Variable              | Value                                  |
| --------------------- | -------------------------------------- |
| `API_INTERNAL_URL`    | `https://mummaxpress-api.onrender.com` |
| `NEXT_PUBLIC_APP_URL` | `https://<your-vercel-app>.vercel.app` |
| `NEXT_PUBLIC_API_URL` | _(empty)_                              |

Set `Cors__AllowedOrigins` on the API to your Vercel URL.

## 7. Troubleshooting

### Frontend deploy failures (most common)

| Symptom / log                                               | Cause                                                      | Fix                                                                                                    |
| ----------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `COPY frontend/package.json: not found`                     | Root Directory set to `frontend` with repo-root Dockerfile | Clear Root Directory **or** use Blueprint defaults (`dockerContext: .`)                                |
| `JavaScript heap out of memory` / exit `137`                | Next.js build exceeds VM RAM                               | Upgrade plan to **Standard**, or the Dockerfile already caps build heap at 4096 MB — re-deploy         |
| Site loads but API/auth 502 / `ECONNREFUSED 127.0.0.1:5181` | `API_INTERNAL_URL` missing at **build** time               | Set `API_INTERNAL_URL=https://mummaxpress-api.onrender.com` on **mummaxpress-web** → **Manual Deploy** |
| Health check failed                                         | Wrong path or app not listening on `PORT`                  | Use health check path `/`; do not hardcode port `3000` in Docker (fixed in `frontend.Dockerfile`)      |
| CORS error in browser                                       | API `Cors__AllowedOrigins` mismatch                        | Set to exact frontend URL (`https://mummaxpress-web.onrender.com`)                                     |

**Cold start latency.** On the free tier Render spins down idle services after
15 minutes. First request after sleep can take 30-60 s. Upgrade to **Starter
($7/mo)** for always-on.

**JWT secret rejected.** If you see _"JWT Secret appears to be a placeholder"_
in logs, your secret contains `CHANGE_THIS`/`DevOnly`/`replace_me` etc.
Replace it with a random 32+ char hex string.

**Migration failures.** Common causes:

- Azure SQL firewall blocks Render → enable _"Allow Azure services..."_ or
  add Render's egress IPs.
- Connection string typo → `/health` returns 503 with the masked connection
  string in logs.
- Missing `Encrypt=True` → Azure SQL refuses the handshake.

**OTPs only in logs.** Expected when `Smtp__Host` is empty — the app runs in
**demo email mode**. Tail Render logs and look for
`Email OTP for <addr>: 123456`. Configure Resend to switch to live mode.

**Phone OTPs return 503.** Intentional. Phone (`/auth/send-otp`) is gated
until the MSG91 template is approved. Email OTP is the only live channel.

## 8. Custom domain & HTTPS

Render handles HTTPS automatically with a free Let's Encrypt cert. To attach
a custom domain:

1. Service → **Settings** → **Custom Domains** → add `api.mummaxpress.com`.
2. Add the `CNAME` record Render shows you to your DNS provider.
3. Wait 2-5 minutes — cert provisions automatically.
4. Update `Cors__AllowedOrigins` and any frontend env vars to use the new
   hostname.

## 10. Manual steps the AI cannot do for you

1. Create the Azure SQL Database and copy the connection string into
   `ConnectionStrings__DefaultConnection`.
2. _(Optional)_ Sign up for Resend, verify a sender domain, paste the API key
   into `Smtp__Password`, paste your verified address into `Smtp__FromEmail`.
3. _(Optional)_ Provision an Upstash Redis DB and paste the `rediss://...`
   URL into `ConnectionStrings__Redis`.
4. Set `NEXT_PUBLIC_APP_URL` on **mummaxpress-web** and re-deploy (section 6).
5. Set `Cors__AllowedOrigins` on the API to your frontend Render URL.
6. Flip `Database__SeedOnStartup` to `true` for the first deploy, then back to
   `false` (section 4).
